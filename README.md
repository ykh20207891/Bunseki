# 仮想通貨 データ蓄積 & ランキング予測

CoinGecko から時価総額上位500銘柄の日次データとニュースを毎日集めて SQLite に貯め、
「次の7日間で相対的に強そうな銘柄」をランキングするための分析基盤です。

> **これは売買推奨ツールではありません。** 出力は統計モデルによる相対順位スコアです。
> 上昇を保証するものではなく、市場全体が下げれば上位銘柄も下がります。
> 分析そのものを目的とし、結果が当たったらラッキー、という位置づけで使ってください。

### collect.bat は必ず CRLF 改行で保存すること

**LF だけで保存すると cmd.exe が `if` ブロックを解析できず、何も実行しないまま
終了コード 0（成功）を返します。** タスクスケジューラは「成功」と記録するため、
データが増えていないことに気づくまで発覚しません（実際に 2026-08-25 の
日次実行がこれで空振りしました）。

編集したら必ず改行コードを確認してください。

```bash
python -c "import pathlib;p=pathlib.Path('collect.bat');p.write_bytes(p.read_bytes().replace(b'

',b'
').replace(b'
',b'

'))"
```

ダッシュボードには**データ鮮度の警告バナー**を入れてあります。
最新スナップショットが当日でなければ、冒頭に「データが N 日前で止まっています」と
赤いバナーが出ます。同じ見落としを繰り返さないための保険です。

### TLS についての注意

この PC は **Avast アンチウイルスの Web シールドが HTTPS を復号**しており、
差し替えられた証明書を Python の OpenSSL 3.5 が拒否します
（`CERTIFICATE_VERIFY_FAILED: Basic Constraints of CA cert not marked critical`）。

対策として `truststore`（Windows ネイティブの証明書検証を使う）を導入済みです。
それでも失敗した場合は Windows 同梱の `curl.exe` に自動フォールバックします。
**Avast の設定は変更していません。**

## 3. クラウド実行（GitHub Actions）

PC の電源に依存せず毎日動かすための構成です。

```
GitHub Actions（毎日 00:10 UTC = 09:10 JST）
   │
   ├─ Release "data" から crypto.db / icons / raw を復元
   ├─ src/daily.py を実行（収集 → ニュース → 翻訳 → アイコン → 予測 → 画面）
   ├─ 更新した DB を Release "data" に上書き保存
   └─ ダッシュボードを GitHub Pages へデプロイ
```

### なぜ DB を Release に置くのか

`crypto.db` は 23MB あり、毎日コミットすると git 履歴が年間数GBに膨れます。
Release のアセットは履歴に残らず上書きできるため、ここに置いています。
リポジトリにはコードだけが入ります。

### 初回セットアップ手順

**1. GitHub で公開リポジトリを作る**（例: `crypto-analysis`）

**2. このフォルダを push する**

```bash
git remote add origin https://github.com/<ユーザー名>/<リポジトリ名>.git
```
```bash
git branch -M main && git push -u origin main
```

**3. Pages を有効化**

`Settings` → `Pages` → **Source を「GitHub Actions」に変更**
（「Deploy from a branch」ではありません）

**4. 蓄積済みデータをアップロード**

`Releases` → `Create a new release` で以下を設定します。

| 項目 | 値 |
|---|---|
| Tag | `data` |
| Title | 蓄積データ |
| 添付ファイル | `crypto.db.gz` `icons.tar.gz` `raw.tar.gz` |

この3ファイルはこのフォルダの直下に生成済みです（合計約9MB）。
ドラッグ&ドロップで添付できます。

> **先にアップロードしてください。** 空の状態でワークフローを走らせると、
> 365日分のバックフィルが無い DB から再出発することになります。

**5.（推奨）CoinGecko の API キーを登録**

`Settings` → `Secrets and variables` → `Actions` → `New repository secret`

| 項目 | 値 |
|---|---|
| Name | `COINGECKO_API_KEY` |
| Secret | `CG-xxxxxxxx`（無料の Demo キー） |

GitHub の実行環境は多数の利用者と IP を共有するため、キー無しだと
CoinGecko のレート制限に当たりやすくなります。**公開リポジトリなので
`config.json` には絶対に書かないでください。**

**6. 手動で1回実行して確認**

`Actions` → `日次収集` → `Run workflow`

成功すると `Settings` → `Pages` に公開 URL が表示されます。
以降は毎日 09:10 JST に自動更新されます。

### 運用上の注意

- **スケジュールは最大1時間ほど遅延することがあります**（Actions の混雑時）。
  日次データなので実害はありません。
- **60日間リポジトリに動きが無いと、スケジュール実行が自動停止されます。**
  GitHub から警告メールが届くので、再有効化するか何かコミットしてください。
- ワークフローは各ステップが独立して失敗を許容します。価格収集だけは
  全ての前提なので、失敗した場合はそこで中断します。
- 実行ログは Actions の成果物として14日間保存されます。

### ローカル実行との関係

`collect.bat` も `src/daily.py` を呼ぶだけなので、**ローカルとクラウドで
まったく同じ処理**が走ります。クラウドに移した後もローカルで動かせますが、
DB が二重管理になるので**どちらか一方に決めて運用してください。**

## 5. ニュースデータについて

### 収集元

| ソース | 取得できるもの | 過去に遡れるか |
|---|---|---|
| RSS 日本語3媒体（CoinPost / あたらしい経済 / CoinDesk JAPAN） | 日本語の見出し・要約・センチメント | **× 不可** |
| RSS 英語10媒体（CoinDesk / Cointelegraph / Decrypt など） | 見出し・要約・リンク・センチメント（見出しは日本語訳を付与） | **× 不可**（各フィードは最新10〜60件のみ） |
| GDELT DOC 2.0 API | キーワード単位の日次ニュース量・平均トーン | **○ 可能**（無料で365日分。API キー不要） |

つまり **過去のニュース「記事そのもの」は無料では取れません**が、
**「その銘柄がどれだけ報道され、そのトーンがどうだったか」という日次の集計値は
GDELT で過去1年分まで遡れます**。特徴量として使うぶんにはこちらで十分です。

GDELT はレート制限が非常に厳しく、**一度ブロックされると 20 時間以上解除されません**
（ブラウザの User-Agent に変えても 429 のままでした）。連続で叩くほど悪化するので、
失敗したら間を空けてください。`--sleep 15` 以上を推奨します。
進捗は保存されるので、後日実行すれば続きから進みます。

> 2026-08-25 時点で GDELT のバックフィルは未実施です。ブロックが解除されたら
> `python src/news_backfill.py --limit 100 --sleep 20` を実行してください。

### 日本語化

日本語media の見出しはそのまま使います（翻訳の質の問題が起きない）。
英語media の見出しは MyMemory の無料APIで機械翻訳し、`title_ja` に保存します。

- API キー不要。ただし匿名枠は**1日5,000文字**なので、ダッシュボードに実際に表示する
  最新の見出しだけを訳し、結果は保存して二度と訳しません。
- 機械翻訳は暗号資産の文脈で崩れやすい（"rally"→「ラリー」、`$ 80 K` のような
  空白混入）ので、用語辞書と正規表現で後処理しています（`translate.py` の `polish`）。
- それでも訳は硬いです。**質を求めるなら日本語media の記事を見てください。**
  ダッシュボードでは機械翻訳の見出しに「自動翻訳」バッジを付けて区別しています。

### 日本語記事の銘柄マッチ

日本語記事は「ビットコイン」のようにカタカナで書くため、英語名では一致しません。
カタカナ名→シンボルの対応表を持たせています（`_JA_NAME_TO_SYMBOL`）。

「ビットコインキャッシュ」には「ビットコイン」が含まれるので、
長い名前の出現回数を差し引いて、独立した言及が残る場合だけ採用します。
感情辞書も日本語用（`POSITIVE_JA` / `NEGATIVE_JA`）を別に持ち、
本文に日本語が含まれるかで自動的に切り替えます。

### センチメント判定

暗号資産ニュース向けにチューニングした単語辞書ベースです（`src/news.py` の `POSITIVE` / `NEGATIVE`）。
学習済みモデルではなく辞書にしたのは、**なぜそのスコアになったか説明できる**ためです。
否定表現（"not bullish"）は扱っていません。見出し中心の短文が対象なので実用上は概ね機能します。

### 銘柄マッチの誤検出対策

`Just` / `Would` / `Cash` / `Cross` のような一般英単語と同じ名前の銘柄が実在するため、
素朴に名前一致させると大量の誤検出が出ます。以下で抑えています。

- 銘柄名が一般英単語1語のみ、または3文字以下 → 名前一致だけでは採用せず、シンボルの一致も要求
- シンボル一致は3文字以上かつストップリスト外のみ（`ETF` `SEC` `CEO` などを除外）
- 辞書やルールを変えたら `python src/news.py --rematch` で蓄積済み記事を再処理

## 6. 設計上の考え方

### なぜ「絶対リターン」ではなく「相対順位」を予測するのか

暗号資産はほぼ全銘柄が BTC と一緒に動きます。絶対リターンを予測しようとすると、
モデルは「明日の市場全体の方向」を当てにいくことになり、これはほぼ不可能です。
そこで **「その日のユニバースの中でどれが相対的に強いか」** という問題に置き換えます。
市場全体の方向は予測せず、銘柄選択だけに絞ることで、予測可能性のある部分に集中します。

そのため特徴量も目的変数も、日ごとに **クロスセクション順位（0〜1）** に変換しています。
レジームが変わってもスケールが安定し、外れ値にも強くなります。

### ユニバース選定（`features.py` の `DEFAULT_UNIVERSE`）

以下を除外しています。除外しないと、実質取引できない銘柄や
値動きしない銘柄がランキング上位を埋めて結果が無意味になります。

| 条件 | 理由 |
|---|---|
| 時価総額 3,000万ドル未満 | 板が薄すぎて統計が成立しない |
| 7日平均出来高 100万ドル未満 | 実質売買できない |
| 出来高/時価総額 < 0.2% | 数字だけ大きい実体のない銘柄 |
| 60日ボラ < 1% | ステーブルコイン（USDT/USDC等）を自動除外 |
| 14日ボラ < 0.5% | 一度きりの価格改定でボラが跳ねたステーブルコインを除外 |
| 履歴 90日未満 | 特徴量が計算できない |
| Wrapped / Staked / トークナイズ株式 | 原資産と重複するため |
| 金連動トークン（XAUT/PAXG等） | 金価格の写しであり暗号資産の値動きではないため |

### 特徴量

**価格系（39個）**
- モメンタム: 1/3/7/14/30/60/90日リターン、加速度、1日リバーサル
- リスク: 7/14/30/60日ボラティリティ、リスク調整モメンタム
- 規模: 対数時価総額、対数出来高
- 流動性: 回転率、回転率サージ、出来高サージ、Amihud 非流動性指標
- レンジ内位置: 14/30/90日の高値・安値からの距離、移動平均乖離
- 順位変化: 時価総額順位の7日・30日変化
- BTC対比: 超過リターン、BTCとの相関
- 地合い: BTC7日リターン、BTCボラ、上昇銘柄比率

**ニュース系（9個・データが貯まったら自動で有効化）**
- 言及数 1日/7日/30日、注目度サージ、全体に占める言及シェア
- センチメント 1日/7日/30日、その変化
- GDELT のニュース量・トーンとその変化

ニュース特徴量は蓄積が **60日** に満たないうちは自動的に除外されます
（`build_dataset(min_news_days=60)`）。過去に存在しない列を学習に混ぜると
「その列が NaN かどうか」で時期を判別してしまい、リークの温床になるためです。

### 検証の作法

- **エンバーゴ**: 目的変数が t→t+7 で重なるため、学習期間と検証期間の間に
  7日の空白を入れています。入れないとリークして成績が過大評価されます。
- **ベースライン比較必須**: 単純な7日モメンタム等と必ず比較します。
  機械学習がそれに勝てていなければ「何も足していない」と判断します。
- **t値は重複を補正**: 日次ICは強く自己相関するので、標準誤差は
  「有効サンプル数 = 日数 / horizon」で計算しています。

## 7. 現時点の検証結果（2026-08-24 時点）

過去365日 × 500銘柄（学習72,109行・検証21期間）でのウォークフォワード検証結果です。

### 予測力（日次スピアマンIC）

| 手法 | 平均IC | t値 | 勝率 |
|---|---:|---:|---:|
| **モデル(GBDT)** | **+0.0755** | **+3.52** | 81.0% |
| 7日モメンタム | -0.0562 | -2.03 | 33.8% |
| 30日モメンタム | -0.0231 | -0.77 | 50.7% |
| 1日リバーサル | +0.0292 | +1.28 | 62.7% |
| 出来高サージ | -0.0133 | -0.81 | 47.2% |

IC は全ベースラインを明確に上回っています。BTCベータ・地合い特徴量を除外しても
IC は 0.075 のまま維持されたので、「BTCとの連動度で賭けているだけ」ではありません。

### ただし、取引可能な優位性はほぼ消える

| 手法 | 上位10・平均/回 | 対ユニバース |
|---|---:|---:|
| モデル(GBDT) | +3.91% | +2.57% |
| **30日モメンタム** | **+5.71%** | **+4.37%** |
| 7日モメンタム | +4.55% | +3.21% |
| ユニバース等加重 | +1.34% | — |

**モデルは単純な30日モメンタムに負けています。** IC が高いのに
ポートフォリオで負けるのは、IC が全銘柄の順位相関を測るのに対し、
上位10銘柄の成績は極端な裾だけで決まるためです。

### 生存者バイアスの診断（自動実行）

| 対象 | 銘柄数 | 平均IC | t値 | 対ユニバース |
|---|---:|---:|---:|---:|
| 全銘柄 | 339 | +0.0755 | +3.52 | +2.57% |
| 2025-08-25 時点で 5,000万ドル以上 | 258 | +0.0707 | +3.16 | +1.91% |
| 2025-08-25 時点で 2億ドル以上 | 196 | +0.0701 | +2.54 | **+0.15%** |

「当時から大きかった銘柄」に絞ると **超過リターンが +2.57% → +0.15% に崩壊**します。
元の成績の大部分は実力ではなく、**当時小さくてその後に急騰し上位500に入ってきた
銘柄を最初から知っていた**ことによるものでした。

### 結論

- 弱いながら本物のクロスセクション順位シグナルはありそう（最も厳しい条件でも t=2.54）
- しかし**取引可能な超過リターンとしては、手数料を引く前でほぼゼロ**
- 単純な30日モメンタムに勝てていない
- **現時点では「使える予測モデルができた」とは言えません**

これは失敗ではなく、検証が正しく機能した結果です。バイアスを潰さずに
「週+3.9%」だけ見ていたら、実際に運用して損をしていました。
今後は `evaluate.py` の実運用記録（生存者バイアスなし）を積み上げて判断します。

## 8. 既知の限界（重要）

1. **生存者バイアス** — バックフィルの対象は「実行時点の上位500銘柄」です。
   過去に上位だったが消えた銘柄は含まれません。したがってバックフィル期間の
   検証結果は実運用より良く出ます。**日次収集で貯まる分にはこのバイアスはありません。**
   最終的には `evaluate.py`（実運用記録の答え合わせ）の数字だけを信用してください。

2. **手数料・スリッページ未考慮** — バックテストは約定コストをゼロとしています。
   小型銘柄では往復数%かかることもあり、これだけで超過リターンは消え得ます。

3. **データ粒度** — 1日1点のスナップショットです。日中の値動きは見ていません。

4. **サンプル数** — 365日 × 7日先予測では、独立なサンプルは実質50程度しかありません。
   良い数字が出ても偶然の可能性が高いです。日次収集を続けて増やす必要があります。

5. **ニュースの過去データは集計値のみ** — GDELT は日次のニュース量とトーンだけで、
   個別記事は取れません。また英語ソースのみです。

6. **上場ペア・取引所の情報を持っていない** — 実際に日本の取引所で買えるかは別問題です。

## 9. API キー（推奨）

キー無しの公開 API はレート制限が非常に厳しく（実測で約10リクエスト/分）、
バックフィルに数時間かかります。**無料の Demo キー**を取ると 30リクエスト/分・
月10,000リクエストになり、大幅に速く・安定します。

1. https://www.coingecko.com/en/api/pricing で **Demo (Free)** に登録
2. ダッシュボードで API キーを発行
3. `config.json` の `coingecko_api_key` に貼り付ける
   （または環境変数 `COINGECKO_API_KEY` に設定。こちらが優先されます）

```json
{
  "coingecko_api_key": "CG-xxxxxxxxxxxxxxxx",
  "coingecko_api_plan": "demo"
}
```
